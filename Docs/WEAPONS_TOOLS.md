# 废土回路：武器与工具科技分支接入大纲

日期：2026-11-21。原规划核对基线：`330261f`（历史快照）。状态：**首批P0装备研究已接入当前源码：W00–W11共12项武器研究、T00–T01共2项工具研究；现行科技树为80个节点（73项研究、7个时代入口），保存格式为v19、工业物品66槽。P1/P2/P3仍为规划；T11便携辐射监测工具仍未实现。**

## 1. 范围与交付边界

武器与工具依附现有原始、水力、蒸汽、LV、MV、HV、核工业七时代展开。工业工艺提供材料和加工能力，装备研究开放具体制作配方；研究由全队共享，装备归属、角色技能、经验和属性仍由个人保存。

首批已将现有装备纳入可解释的研究关系，打通核心判定、制作、弹药、科技树、保存和联机快照。后续再增加早期装备和动力工具。除已有的原始基础工具和块炼铁外，新增装备研究均为可选支线，不加入任何工业时代入口的必需研究掩码，也不让工业主线反向依赖武器产量。

原规划快照 `330261f` 为保存格式v17、工业物品63槽、19类装备与7类配件、64个科技树节点（57个研究节点、7个时代入口），该口径仅作历史基线。辐射阶段的历史快照曾为v17、63槽和66个节点（59项研究、7个时代入口）；P0阶段的基线为v18、63槽、20类装备、7类配件和80个节点（73项研究、7个时代入口）。P0接入14项研究，装备与配件种类沿用原目录；样品费用统一通过`DemoCatalog.Materials`构造，不硬编码历史物品数组长度。

新增的第20类装备为核作业防护服 `GearKind.RadiationSuit=19`，制作已由 `NuclearTech.RadiationProtection` 控制，沿用当前核研究、工作台及材料判定；不再将它重复接入本文规划的武器／工具研究，也不为此增加P0节点。当前核研究与本文预留工具使用各自独立标识，不能把核研究 `RadiationMonitoring=9` 当成工具 `RadiationMonitor=11` 已上线。

现行石斧与石镐允许随身制作。P0阶段的旧配方与v18验证见末尾的阶段记录。P1/P2/P3表内数值仍为规划，需在对应批次从零试玩调平衡。

## 3. 研究与解锁的统一规则

1. 研究条件为“所在时代 + 全部直接前置 + 当前可获得样品 + 真实工业生产记录”。样品由发起者随身库存扣除，研究结果只写入世界状态。
2. 研究仍要求有效存活角色、可见且在交互范围内的工作台和可用操作冷却；一条权威指令完成验证、扣料、置位和反馈，重复指令不得再次扣料。
3. 首批只复用已有`produced[]`及工业研究记录，不新增击杀任务、装备制造计数或依赖本节点产物的试制要求。搬运、拾荒、维修和回收不增加工业实产。
4. 成品使用不增加时代/研究门槛：合法持有的装备可以装备、射击、装填和安装兼容配件，有研究门槛的装备须先解锁才能自主制造。P0配件安装保留工作台、库存和兼容检查，不因时代或制造研究额外拒绝；预装配件继续生效。普通维修和回收沿用既有条件，石器维修使用木材和石材；高级现场维修仍作为可选能力。
5. 材料不足、研究不足、满背包、无工作台和非法目标分别返回具体原因。执行失败不扣材料，不增加耐久或生产记录。
6. 所有直接前置均为AND关系。第一批不引入OR前置，手枪与霰弹枪互不要求先制造对方，配件研究不要求支付成品枪作为样品。
7. 下表的“实产”均指全队真实生产累计值`world.produced[(int)ItemKind.X]`，而非现有库存；已发生的合法工业生产可直接满足条件，研究不会清零工业产量。

### 4.4 使用、维修与拾荒的范围

手工采集需要持用有耐久的匹配工具。树木与补给箱用斧，石材、黏土和矿床用镐，废料堆用扳手。每次工作消耗工具1点耐久，节点耐久归零时一次结算全部剩余物资及适用的附带觅食。背包装不下整份物资时，最后一下暂停且不扣耐久。工具品质影响完成速度。

当前仍无完整的装备拾荒掉落路径，本文的“拾荒可提前使用”仍是后续功能契约，不能作为已有玩法汇报。P0不新增随机装备投放或队友交易；已用显式构造的合法成品夹具验证使用与制造分离，并注明覆盖范围。后续拾荒批次需先定义有限箱库存、装备容量24件、初始耐久、弹匣与配件来源，以及满包、取出、保存和重复交互的守恒行为。

首批不重做维修经济：非石器仍按现有铁锭2+废料1恢复25耐久，工作台、有效目标和耐久上限条件保留；现有回收按制作材料逐项半返、归还已装配件和弹匣弹药。高级装备在早期维修/回收的能力属于保留现状，不视为已具备该装备的自主制造资格，也不贡献研究实产。

- 有线工具要求同楼层、6格内、路径无遮挡的有效接口；接口挂在实际LV网络上，电锯/电钻/检修分别登记5/8/5 kW作业负载，使用既有供电分配结果。仅站在线杆附近不算已供能。

- 工具效率、耐久和噪音分别配置。动力工具的高效率必须进入真实节点余量、容量、冷却与体力结算，不能只改提示文本。燃油余量不足可切回手工工具。

## 8. 数据、核心、保存与网络接入契约

### 8.1 研究数据与节点标识

- 为装备研究定义目录数据：稳定id、显示名、时代、研究域、全部直接前置、样品成本、生产条件、解锁对象和说明。工业前置用带域与时代的`ResearchRef`引用，不把不同目录的bit混在同一掩码。
- 已新增`world.weaponResearch`、`world.toolResearch`两个独立整数位集；当前有效位分别为W00–W11与T00–T01，对应掩码4095与3。后续规划上限16个武器位、13个工具位；非负`int`的位槽限制为0..30，超出时先升级结构，不能继续移位溢出。
- 新世界两个位集均为0。已有Primitive Tools与Bloomery保持唯一权威来源，不复制到新位集，不新增默认全解锁或历史世界旁路。
- 现有工业节点key保持不变；武器节点使用`10000+id`，工具节点使用`20000+id`。已接入显式研究域，父节点继续使用唯一key；不得从key除100/取模反推新节点时代或目录。
- 当前统一查询接口为`Requirement`、`Evidence`、`Known`、`IsGearUnlocked`、`IsPartUnlocked`、`IsAmmoUnlocked`；它们是纯查询。权威执行入口负责扣料、置位，UI不可直接写世界研究位。
- 指令固定为`weapontech arg=id`和`tooltech arg=id`，均小于当前action长度上限16；id为目录枚举值，不接受UI节点key充当研究id。保留现有工业指令。网络端继续按已绑定连接覆盖客户端传入的playerId。
- 失败原因按“时代→工业前置→装备前置→实产→工位/角色→样品”形成稳定展示次序；执行前重新检查全部条件，防止显示后状态改变造成错误扣料。

表内工业前置别名分别对应`PrimitiveTech`、`WaterTech`、`SteamTech`、`LowVoltageTech`、`PetrochemicalTech`与`PrecisionTech`。节点显示顺序使用时代与显式排序值，不使用枚举大小决定先后。`TechnologyTreeModel`的Known、Requirement、Valid、ResearchCount、节点注册、图标与生产证据查询已按研究域路由；时代入口的`AddEraParents`只遍历工业节点，跨域前置使用显式`ResearchRef`和节点key。

### 8.2 制作、生产与生产记录

装备、配件、手工弹药、快捷指令和自动装配分别从对应执行入口调用统一解锁条件；UI禁用只是表现。外部输入需验证目录范围和目标角色，不得接受未知id、越界索引、非法研究位或客户端提供的“已满足条件”。

首批研究不新增装备生产计数。第二批纤维、箭矢、弩箭和维修包属于新增工业物品，统一进入物品计数、背包容量、物流、保存和制作反馈；纤维等手工加工的真实完成才更新`produced[]`。树木采集和拆解依旧不等于制造。

### 8.3 当前格式保存与联机

现行`WorldSimulator.SaveVersion=19`。原始采集改动的验收范围为新世界和当前格式的保存、读取、深拷贝与恢复，不新增旧档迁移或旧研究旁路。

新增位集已接入JSON字段、状态复制、快照构建和档案校验路径；拒绝未知位、缺失必需前置和研究已开但时代不足的非法状态。跨目录依赖按目录定义校验，不因各目录单独掩码合法就接受孤立节点。

当前JSON由Unity `JsonUtility`或CoreChecks启用字段的`System.Text.Json`完成；没有为新位集另造手写序列化器。`WorldSimulator.Validation.CopyAndValidate`、研究状态校验和`WorldSnapshot.ForPlayer`快照复制均保留新分支字段，并检查掩码、时代与前置闭包；不对裁剪后的快照套用要求完整世界实体的校验。联机消息通道当前仍带`v10`后缀，兼容性由票据/快照的SaveVersion判断；载荷版本、通道名和读档格式分别核对。

研究指令走`GameBridge.Send`到房主模拟器，由房主核验角色、材料与生产记录后一次提交。队员离线、死亡、重新加入或更换人物不清空世界研究；客户端仅通过快照看到结果。两人同时提交同一研究最多消耗一次样品，后到命令返回已完成。

## 9. 科技树与背包接入
