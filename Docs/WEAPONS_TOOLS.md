# 废土回路：武器与工具科技分支接入大纲

日期：2026-11-21。原规划核对基线：`330261f`（历史快照）。状态：**本文规划的装备研究、物品与工具分支仍为设计与接入准备；核工业已另行接入辐射监测与防护服，不代表本文预留工具已实现。**

## 1. 范围与交付边界

武器与工具依附现有原始、水力、蒸汽、LV、MV、HV、核工业七时代展开。工业工艺提供材料和加工能力，装备研究开放具体制作配方；研究由全队共享，装备归属、角色技能、经验和属性仍由个人保存。

首批先将现有装备纳入可解释的研究关系，打通核心判定、制作、弹药、科技树、保存和联机快照。后续再增加早期装备和动力工具。除已有的原始基础工具和块炼铁外，新增装备研究均为可选支线，不加入任何工业时代入口的必需研究掩码，也不让工业主线反向依赖武器产量。

原规划快照 `330261f` 为保存格式v17、工业物品63槽、19类装备与7类配件、64个科技树节点（57项研究、7个时代入口），该口径仅作历史基线。当前辐射阶段仍为v17、63槽与7类配件，装备增为20类，科技树为66节点（59项研究、7个时代入口）。首批14项P0装备研究计划保持不变，不增加物品、装备或配件种类；样品费用统一通过`DemoCatalog.Materials`构造，不硬编码历史物品数组长度。

新增的第20类装备为核作业防护服 `GearKind.RadiationSuit=19`，制作已由 `NuclearTech.RadiationProtection` 控制，沿用当前核研究、工作台及材料判定；不再将它重复接入本文规划的武器／工具研究，也不为此增加P0节点。当前核研究与本文预留工具使用各自独立标识，不能把核研究 `RadiationMonitoring=9` 当成工具 `RadiationMonitor=11` 已上线。

本次文档交付不修改游戏代码、配方或保存格式。表内数值是下一轮实施的初始配置，需经从零试玩调平衡。

## 3. 研究与解锁的统一规则

1. 研究条件为“所在时代 + 全部直接前置 + 当前可获得样品 + 真实工业生产记录”。样品由发起者随身库存扣除，研究结果只写入世界状态。
2. 研究仍要求有效存活角色、可见且在交互范围内的工作台和可用操作冷却；一条权威指令完成验证、扣料、置位和反馈，重复指令不得再次扣料。
3. 首批只复用已有`produced[]`及工业研究记录，不新增击杀任务、装备制造计数或依赖本节点产物的试制要求。搬运、拾荒、维修和回收不增加工业实产。
4. 成品使用不增加时代/研究门槛：合法持有的装备可以装备、射击、装填和安装兼容配件，自主制造受研究限制。首批配件安装保留工作台、库存和兼容检查，移除仅因时代不足而拒绝的条件；预装配件继续生效。普通维修和回收沿用既有条件，仅修正石器维修的石材类型；高级现场维修另作为可选能力。
5. 材料不足、研究不足、满背包、无工作台和非法目标分别返回具体原因。执行失败不扣材料，不增加耐久或生产记录。
6. 所有直接前置均为AND关系。第一批不引入OR前置，手枪与霰弹枪互不要求先制造对方，配件研究不要求支付成品枪作为样品。
7. 下表的“实产”均指全队真实生产累计值`world.produced[(int)ItemKind.X]`，而非现有库存；已发生的合法工业生产可直接满足条件，研究不会清零工业产量。

工业主线仍可用装配机配方148/149/150生产电缆、电机、继电器，满足LV自动装配与后续时代进度，不要求制造弹药。指南和被锁的默认配方提示应指向这些非武器生产选项，避免把武器支线变成实际操作中的隐性必修。

### 4.4 使用、维修与拾荒的范围

当前无完整的装备拾荒掉落路径，本文的“拾荒可提前使用”是后续功能契约，不能作为已有玩法汇报。P0不新增随机装备投放或队友交易；用显式构造的合法成品夹具验证使用与制造分离，并注明覆盖范围。后续拾荒批次需先定义有限箱库存、装备容量24件、初始耐久、弹匣与配件来源，以及满包、取出、保存和重复交互的守恒行为。

首批不重做维修经济：非石器仍按现有铁锭2+废料1恢复25耐久，工作台、有效目标和耐久上限条件保留；现有回收按制作材料逐项半返、归还已装配件和弹匣弹药。高级装备在早期维修/回收的能力属于保留现状，不视为已具备该装备的自主制造资格，也不贡献研究实产。

- 采集按“基础量+工具奖励”计算，再限制到节点余量和背包容量：现有石制+2、钢制+5及冷却系数作为基线，铁制位于二者之间；满包或节点不足不虚增收获、耐久损耗或产量。
- 木矛、铁矛通过距离与攻击间隔体现差异；石刃、砍刀偏短距。上述数值与现有军刀、体力和敌人受击判定一起试玩后再固定。
- 弓弩复用权威瞄准、遮挡、动物/丧尸命中、弹药扣除和装填流程；首版沿当前射线规则判定命中，以箭矢轨迹区分表现，不新增重力抛物线或独立飞行物模拟。使用显式武器类型，避免把弓弩识别为枪械并开放枪械配件。
- 撬棍只作用于合法废料采集或明确的拆解操作，不将所有自然建筑或玩家设施自动转成可刷材料。
- 基础维修包目标恢复25点耐久；只在目标缺少耐久且能实际恢复时消耗。不能把维修计为制造；回收按原始制作成本和当前耐久设上限，循环修理回收不得增加资源。

供能实施必须满足：

- 有线工具要求同楼层、6格内、路径无遮挡的有效接口；接口挂在实际LV网络上，电锯/电钻/检修分别登记5/8/5 kW作业负载，使用既有供电分配结果。仅站在线杆附近不算已供能。
- 供电负载先在固定tick登记，获得有效分配后再执行一次作业。停电、跳闸、满包、非法目标或电缆距离不足时不结算收获，不扣耐久；界面提示具体原因。
- 燃油工具使用装备独立的整数作业余量：每1柴油补充100单位，上限100；油锯每次合法作业消耗5，便携钻消耗8。只有剩余容量可容纳整份燃料时才允许补充，首版不允许倒出燃油。
- 序列化保存每件工具的余量，深拷贝不共享可变对象；掉落、拾取、死亡、回收和转交不得重置余量。
- 工具效率、耐久和噪音分别配置。动力工具的高效率必须进入真实节点余量、容量、冷却与体力结算，不能只改提示文本。燃油余量不足可切回手工工具。

## 8. 数据、核心、保存与网络接入契约

### 8.1 研究数据与节点标识

- 为装备研究定义目录数据：稳定id、显示名、时代、研究域、全部直接前置、样品成本、生产条件、解锁对象和说明。工业前置用带域与时代的`ResearchRef`引用，不把不同目录的bit混在同一掩码。
- 新增`world.weaponResearch`、`world.toolResearch`两个独立整数位集；本轮首批有效位分别为W00–W11与T00–T01，对应掩码4095与3。当前规划上限16个武器位、13个工具位；非负`int`的位槽限制为0..30，超出时先升级结构，不能继续移位溢出。
- 新世界两个位集均为0。已有Primitive Tools与Bloomery保持唯一权威来源，不复制到新位集，不新增默认全解锁或历史世界旁路。
- 现有工业节点key保持不变；武器节点预留`10000+id`，工具节点预留`20000+id`。新增显式研究域，父节点继续使用唯一key；不得从key除100/取模反推新节点时代或目录。
- 建议统一查询接口为`Requirement`、`CanResearch`、`Known`、`IsGearUnlocked`、`IsPartUnlocked`、`IsAmmoUnlocked`；它们是纯查询。权威执行入口负责扣料、置位，UI不可直接写世界研究位。
- 指令固定为`weapontech arg=id`和`tooltech arg=id`，均小于当前action长度上限16；id为目录枚举值，不接受UI节点key充当研究id。保留现有工业指令。网络端继续按已绑定连接覆盖客户端传入的playerId。
- 失败原因按“时代→工业前置→装备前置→实产→工位/角色→样品”形成稳定展示次序；执行前重新检查全部条件，防止显示后状态改变造成错误扣料。

表内工业前置别名分别对应`PrimitiveTech`、`WaterTech`、`SteamTech`、`LowVoltageTech`、`PetrochemicalTech`与`PrecisionTech`。节点显示顺序使用时代与显式排序值，不使用枚举大小决定先后。`TechnologyTreeModel`的Known、Requirement、Valid、ResearchCount、节点注册、图标与生产证据查询必须按研究域路由；时代入口的`AddEraParents`只遍历工业节点，现有按key取模递归寻找祖先的逻辑也要改用显式域与时代。

### 8.2 制作、生产与生产记录

装备、配件、手工弹药、快捷指令和自动装配分别从对应执行入口调用统一解锁条件；UI禁用只是表现。外部输入需验证目录范围和目标角色，不得接受未知id、越界索引、非法研究位或客户端提供的“已满足条件”。

首批研究不新增装备生产计数。第二批纤维、箭矢、弩箭和维修包属于新增工业物品，统一进入物品计数、背包容量、物流、保存和制作反馈；纤维等手工加工的真实完成才更新`produced[]`。树木采集和拆解依旧不等于制造。

### 8.3 当前格式保存与联机

基线`WorldSimulator.SaveVersion=17`，本方案首批目标为v18；若接入前主线已升级，则从当时版本再递增一次，并同步世界/网络协议检查。只保证新世界和该次当前格式的保存、读取、深拷贝与恢复，不新增旧档迁移或旧研究旁路。

新增位集必须在JSON编解码、状态复制、快照构建和档案校验的所有路径中检查；拒绝未知位、缺失必需前置和研究已开但时代不足的非法状态。跨目录依赖按目录定义校验，不因各目录单独掩码合法就接受孤立节点。

当前JSON由Unity `JsonUtility`或CoreChecks启用字段的`System.Text.Json`完成；不要为新位集另造一套手写序列化器。`WorldSimulator.Validation.CopyAndValidate`会重建世界，必须显式接入新分支的复制校验，否则字段即使已被JSON读取也会在恢复时丢失。`WorldArchive`磁盘往返与`WorldSnapshot.ForPlayer`过滤快照分别验证，客户端接收快照目前不执行完整存档校验，新位集应至少校验掩码、时代与前置闭包；不能对裁剪后的快照直接套用要求完整世界实体的校验。联机消息通道当前仍带`v10`后缀，兼容性由票据/快照的SaveVersion判断；载荷版本、通道名和读档格式分别核对。

研究指令走`GameBridge.Send`到房主模拟器，由房主核验角色、材料与生产记录后一次提交。队员离线、死亡、重新加入或更换人物不清空世界研究；客户端仅通过快照看到结果。两人同时提交同一研究最多消耗一次样品，后到命令返回已完成。
